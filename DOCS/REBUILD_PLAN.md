# План пересборки бота M158

Этот документ описывает архитектуру и план разработки для новой версии Telegram-бота. Цель — создать более модульного, масштабируемого и поддерживаемого бота, сохранив и улучшив все успешные идеи из предыдущей версии.

## 1. Основные принципы и цели

- **Модульность**: Максимальное разделение ответственности. Логика, работа с данными и отображение (клавиатуры, тексты) должны быть независимы друг от друга.
- **Масштабируемость**: Использование PostgreSQL в качестве основной базы данных с самого начала для обеспечения надежной одновременной работы и подготовки к интеграции с веб-сайтом.
- **Тестируемость**: Структура кода должна позволять легко писать unit- и интеграционные тесты для отдельных компонентов.
- **Сохранение лучшего UX**: Полностью воспроизвести и улучшить ключевые "фишки", которые делают бота удобным: принцип "одного экрана", интерактивный слайдер, "умные" фильтры и т.д.

## 3. Стек технологий

- **Бот**: Python 3.11+, Aiogram 3.x
- **База данных**: PostgreSQL
- **Взаимодействие с БД**: SQLAlchemy 2.0 (AsyncIO engine + ORM)
- **Сайт**: Django, Django Rest Framework (для будущего API)

## 4. Ключевые концепции для реализации

Это "фишки", которые мы переносим из старого проекта, но реализуем в новой, более чистой архитектуре.

1.  **Менеджер сообщений ("Принцип одного экрана")**
    - **Реализация**: Будет реализован как `middleware`, который передает в каждый хендлер сервис `MessageManager`. Этот сервис будет отслеживать ID "активного" сообщения и принимать решение: отредактировать его или удалить и отправить новое.

2.  **Интерактивный слайдер**
    - **Реализация**: Логика слайдера будет вынесена в `services/slider_service.py`. Он будет управлять состоянием (текущий слайд, пауза/плей). Хендлеры в `handlers/browsing.py` будут вызывать этот сервис, а функции из `keyboards/inline.py` — генерировать для него клавиатуры.

3.  **"Умные" фильтры**
    - **Реализация**:
        - `services/filter_service.py`: Управляет состоянием фильтров (установка, сброс, иерархия).
        - `handlers/filtering.py`: Принимает колбэки от кнопок фильтров и вызывает `FilterService`.
        - `keyboards/inline.py`: Перед генерацией клавиатуры фильтров обращается к репозиториям, чтобы проверить наличие товаров и скрыть "пустые" кнопки.

4.  **Слой данных (Repository Pattern + SQLAlchemy ORM)**
    - **Отказ от монолитного класса**: Вместо одного гигантского класса `BotDatabase` с SQL-запросами в строках, мы будем использовать:
        - **ORM Модели** (`db/models.py`): Классы Python, описывающие таблицы в БД. SQLAlchemy будет сам генерировать SQL-запросы.
        - **Репозитории** (`db/repositories/`): Классы, инкапсулирующие логику запросов к конкретной таблице. Например, `ProductRepository` будет иметь методы `get_by_id(product_id)`, `get_filtered(filters)` и т.д. Это делает остальной код независимым от способа хранения данных.

## 5. План работ

1.  **Этап 1: Настройка окружения (Bootstrap)**
    - Создать структуру папок согласно плану.
    - Инициализировать `pip` / `poetry`, установить зависимости (`aiogram`, `sqlalchemy`, `asyncpg`).
    - Настроить `app/config.py` и `app/loader.py` для подключения к PostgreSQL.

2.  **Этап 2: Слой данных**
    - Описать основные ORM-модели в `app/db/models.py` (User, Product, Size, ProductVariant).
    - Реализовать базовый репозиторий с общими методами (`add`, `get_by_id`).
    - Реализовать `UserRepository` и `ProductRepository`.

3.  **Этап 3: Базовый запуск**
    - Реализовать хендлер `/start` в `app/handlers/common.py`.
    - Реализовать простую генерацию главного меню.
    - Добиться успешного запуска бота и регистрации нового пользователя в базе данных PostgreSQL.

4.  **Этап 4: Реализация фичей (помодульно)**
    - Реализовать отображение профиля пользователя.
    - Реализовать базовую админ-панель.
    - Реализовать систему фильтрации (логика + UI).
    - Реализовать слайдер для просмотра товаров.
    - ... и так далее по списку фичей.

5.  **Этап 5: Интеграция с Django**
    - Инициализировать проект в `m158site/`.
    - Настроить Django на использование той же базы PostgreSQL.
    - Использовать `python manage.py inspectdb` для автоматической генерации Django-моделей из существующей схемы БД, созданной ботом.
    - Создать админ-панель Django для удобного управления данными.
