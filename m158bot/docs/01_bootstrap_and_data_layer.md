# Шаг 1: Настройка окружения и слоя данных

Этот этап закладывает фундамент для нового бота. Были выполнены следующие ключевые шаги в соответствии с `REBUILD_PLAN.md`.

## 1. Настройка конфигурации (`app/config.py`)

- Создан файл для управления конфигурацией приложения.
- Используется библиотека `pydantic-settings` для загрузки переменных из `.env` файла.
- Определены строго типизированные классы `BotSettings` и `DbSettings`, что предотвращает ошибки из-за отсутствующих или некорректных переменных окружения.
- Создана удобная функция `get_settings()`, которая возвращает единый объект `Settings` со всеми настройками приложения.

## 2. Инициализация основных компонентов (`app/loader.py`)

- Создан файл, отвечающий за инициализацию и хранение глобальных объектов бота.
- **SQLAlchemy Engine**: Создается асинхронный "движок" (`engine`) для подключения к PostgreSQL. Строка подключения берется из объекта `settings`, созданного на предыдущем шаге.
- **Фабрика сессий**: Инициализирована `db_session_factory` — фабрика, которая будет поставлять асинхронные сессии для каждого запроса к базе данных.
- **Bot и Dispatcher**: Созданы базовые объекты `aiogram` — `bot` и `dp`.

## 3. Определение ORM-моделей (`app/db/models.py`)

Это ключевое архитектурное изменение по сравнению со старым ботом.

- **Переход на ORM**: Вместо написания "сырых" SQL-запросов, мы определяем структуру таблиц БД в виде Python-классов, наследуемых от `DeclarativeBase` из SQLAlchemy.
- **Первые модели**: В качестве основы были определены две главные модели:
    - `User`: Описывает таблицу `users` со всеми полями пользователя.
    - `Product`: Описывает таблицу `products` для каталога товаров.
- **Преимущества**: Такой подход делает код более читаемым, безопасным (защита от SQL-инъекций), легко расширяемым и независимым от конкретной СУБД (в будущем можно будет легко сменить PostgreSQL на что-то другое).
