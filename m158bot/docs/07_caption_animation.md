# Этап 7: Реализация анимации "Бегущая строка"

На этом этапе был воссоздан финальный элемент приветственного экрана из старого бота — эффект "живого" интерфейса через анимацию текста.

## Принцип работы

Логика анимации разделена на три части: источник фраз, сервис-аниматор и обработчик-контроллер.

### 1. Лексикон (`app/lexicon.py`)

Для хранения списка фраз, которые будут циклически меняться, был создан специальный файл. Это позволяет легко изменять, добавлять или удалять фразы, не затрагивая основной код.

### 2. Сервис-аниматор (`app/services/caption_service.py`)

В сервис, отвечающий за генерацию текста, были добавлены две ключевые модификации:

-   Функция `get_start_caption` была доработана, чтобы принимать опциональный параметр `animation_phrase` и добавлять его в конец основного текста.
-   Была создана новая асинхронная функция `animate_start_caption`. Она является "вечным двигателем" анимации:
    1.  Запускается в бесконечный цикл (`while True`).
    2.  Внутри цикла делает паузу в 3 секунды (`asyncio.sleep(3)`).
    3.  Берет следующую фразу из лексикона.
    4.  Вызывает `get_start_caption`, чтобы сгенерировать полный текст с новой фразой.
    5.  Использует `message_service.edit_caption()` для плавного обновления подписи у уже существующего сообщения с фото.
    6.  Имеет обработку исключений `asyncio.CancelledError` (для штатной остановки) и `TelegramBadRequest` (если сообщение было удалено).

### 3. Обработчик-контроллер (`app/handlers/common.py`)

Обработчик `/start` теперь не только показывает сообщение, но и управляет жизненным циклом анимации:

1.  **Остановка предыдущей задачи:** При каждом вызове `/start` код первым делом обращается к FSM (`state`), находит там предыдущую задачу анимации для этого пользователя (если она была) и немедленно ее отменяет (`task.cancel()`). Это гарантирует, что у одного пользователя никогда не будет запущено две и более анимации одновременно.
2.  **Запуск новой задачи:** После отправки стартового сообщения, обработчик создает новую фоновую задачу анимации с помощью `asyncio.create_task(animate_start_caption(...))`.
3.  **Сохранение задачи:** Ссылка на новую задачу сохраняется в FSM (`state.update_data(animation_task=...)`), чтобы при следующем вызове `/start` ее можно было найти и остановить (см. п.1).

## Итог

Эта реализация полностью копирует поведение старого бота, обеспечивая эффект "бегущей строки" на главном экране, и делает это надежно, с контролем запущенных фоновых задач.
